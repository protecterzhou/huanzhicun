# 环智存 · 产品与数据模型设计 v0.1

> 适用范围：多租户 SaaS（同时支持单租户私有化部署）
> v1 边界：只管理"成果文件"的归档，不管"工作过程执行"
> 通知：仅站内红点

---

## 0. 定位

**一句话**：把"每家公司每年必须交哪些环保资料"变成可配置规则，系统自动生成应归档清单、自动算归档率、自动标逾期临期，让集团总部在督察/审计前不用打电话催资料。

**目标客户**：有排污许可证、要过 ISO14001、要迎中央/省级环保督察的**集团型环保企业**（4~50 家下属公司）。

**差异化**：竞品在"存文件"，我们在"算交没交"。核心资产是**行业模板包**（分类 + 频次 + 截止日规则 + 模板文件），不是代码。

---

## 1. 三条确认带来的关键决策

| 确认 | 决策影响 |
|---|---|
| 卖给别的集团 | 一切配置化：组织树、分类、规则、模板、角色全部租户自定义；新增平台超管后台；新增行业模板包与开通向导 |
| v1 只管成果文件 | 拆掉"年度工作计划核对表"里的过程勾选；改为"任务 → 档案"单向关联（点任务直接跳上传/查看） |
| 仅站内红点 | 必须有"未读红点 + 通知列表页"；因为不推送，**工作台必须承担聚合职责**，否则用户不登录就永远不知道 |

---

## 2. 一处必须立刻改掉的设计

**现状**：登录页让用户自己选「总负责人 / 负责人 / 资料员」三个身份登录。

**问题**：把权限判断交给了用户。任何人点"总负责人"就能试。SaaS 环境下这是越权漏洞。

**改为**：
- 登录页只有 **账号 + 密码**；
- 角色由服务端根据 `user_role` 返回，前端只负责渲染；
- 登录后按角色决定首页默认视图（总负责人看全集团，其余看本公司）；
- 三个角色的差别体现在**数据范围**和**按钮显隐**，不体现在登录入口。

## 3. 核心数据模型

### 3.1 表清单

```
tenant              租户
org                 组织树（集团 / 公司 / 部门）
user                账号
role / permission / role_permission / user_role     RBAC + 数据范围
category            资料分类 + 归档规则（核心）
archive_task        应归档任务（由 category 自动生成）
document            档案记录
document_version    文件版本
audit_log           操作日志
notification        站内通知
template_pack       行业模板包（SaaS 资产）
```

### 3.2 关键字段

**tenant** — 租户
```
id, name, code, plan, deploy_mode(saas|standalone),
status(active|suspended|expired), expire_at, created_at
```

**org** — 组织树
```
id, tenant_id, parent_id, path(物化路径 1/5/12), type(group|company|dept),
name, short_name, sort, status(active|disabled)
```
> 用 `path` 存物化路径，一次 LIKE 查出整棵子树，避免递归查询。`status=disabled` 即"停用"，**不做物理删除**。

**user**
```
id, tenant_id, org_id, username, password_hash(argon2), phone, name, title,
status(active|disabled|locked), fail_count, last_login_at, pwd_changed_at
```

**role / user_role** — RBAC + 数据范围
```
role:  id, tenant_id, code, name, is_system
user_role: user_id, role_id, data_scope(self|self_and_children|all|custom), scope_org_ids
```
> 系统预置 4 个角色，但允许租户自建：`tenant_admin`（总负责人）、`org_admin`（公司负责人）、`clerk`（资料员）、`auditor`（只读审计/督察，限时）。
> `auditor` 是 SaaS 的加分项——督察组来了给个只读账号，到期自动失效。

**category** — 资料分类 + 归档规则（**整个产品的核心表**）
```
id, tenant_id, parent_id, code, name, level,
frequency(month|quarter|year|half_year|once),
due_base(period_end|period_start), due_offset_days,
remind_days,                    -- 提前几天标"临期"
responsible_role,               -- 谁负责交
required,                       -- 是否必交
retention_years,                -- 保留年限（危废台账法定 5 年起）
template_file_id,               -- 模板文件（资料员照着填）
sort, status, source(template|custom)
```

**archive_task** — 应归档任务
```
id, tenant_id, org_id, category_id,
period_type, period_key,        -- 2026-10 / 2026-Q3 / 2026 / ONCE
title, due_date, assignee_id,
status(pending|submitted|done|rejected|waived),
document_id, waived_reason, generated_at
```

**document** — 档案记录
```
id, tenant_id, org_id, category_id, task_id,
title, period_key, year, remark,
status(draft|pending_review|archived|rejected|voided),
current_version_id, created_by, reviewed_by, reviewed_at, deleted_at
```

**document_version** — 文件版本
```
id, document_id, version_no, file_name, object_key,
size, mime, sha256, uploaded_by, created_at, note
```
> `sha256` 是"档案不可篡改"唯一能证明的东西，也是查重（同一文件重复上传）的依据。

**audit_log**
```
id, tenant_id, actor_id, action, target_type, target_id,
detail(json 含 before/after), ip, ua, created_at
```

**notification**
```
id, tenant_id, user_id, type(task_due|task_overdue|review_result|account),
title, body, ref_type, ref_id, read_at, created_at
```

### 3.3 多租户约定（写进规范）

1. **所有业务表带 `tenant_id`**，唯一索引必须包含它：`unique(tenant_id, org_id, category_id, period_key)` 防重复任务。
2. 后端用**中间件强制注入** `tenant_id = 当前登录用户.tid`，禁止从请求参数取，防越权。
3. 对象存储按 `tenant/{tenant_id}/org/{org_id}/{yyyy}/{uuid}` 分前缀，**不暴露原始文件名**。
4. `deploy_mode=standalone` 时租户表只留一条，代码零分支。
5. 预留 `plan`、`expire_at`、用量字段，v1 不收费但要能看。

## 4. 归档任务怎么自动生成（"自动更新提醒"的真正实现）

### 4.1 期次编号规范
```
月报  2026-10
季报  2026-Q3
半年报 2026-H2
年报  2026
一次性 ONCE
```
> 期次必须是**显式字段**，不能像现在这样从标题里猜"9月/Q3"。

### 4.2 截止日计算
```
due_date = (due_base 对应日期) + due_offset_days
月报：period_end + 5   → 10 月报，11-05 截止
季报：period_end + 15
年报：period_end - 11  → 2026 年报，12-20 截止
```
> 现在核对表里"环保制度 每年"12 个月全是横杠，却显示"!"——就是因为**没有 due_date**，逾期算不出来。

### 4.3 生成时机
每天 00:10 跑一次定时任务：
- 为每个 `org × category` 生成**当期 + 下一期**的任务（提前生成一期，避免月初漏发）；
- 生成时校验唯一索引，已存在则跳过（幂等）；
- 任务创建即挂 `assignee_id`（按 `responsible_role` 找对应公司的人）。

### 4.4 免交（waiver）——SaaS 必须做

截图中"高新开发集团总部 → 环保制度"是 `—`，说明有的公司不适用某些分类。**不适用的分类不能算进分母**，否则归档率永远上不去，客户第一天就投诉。

两种实现，建议都要：
1. 分类级：`category` 可挂载到指定 org 子集（`category_org` 关联表）；
2. 任务级：管理员对单条任务标"免交"并填原因，留日志。

## 5. 状态机

```
任务：  pending ──提交──> submitted ──审核通过──> done
           ^                    │
           └──────驳回──────────┘
         pending ──管理员免交──> waived

派生状态（不入库，实时算）：
  overdue   due_date < today 且 status in (pending, rejected)
  due_soon  today <= due_date <= today + remind_days
```

**关键原则**：状态由"有没有归档记录"驱动，**不允许手工勾选完成**。现在核对表能打勾但不上传文件，等于进度数据可以被刷。

---

## 6. 指标口径（全站唯一真源，写进常量）

```
应归档 = 期间内 due_date 已到期 且 status != waived 的任务数
已归档 = 其中 status = done 的任务数
归档率 = 已归档 / 应归档        ※ 按任务计数，不做公司间算术平均
逾期   = due_date < today 且未归档
临期   = today <= due_date <= today + remind_days 且未归档
未来期间不计入任何分母
```

> 你现在首页 67% = (81+64+68+55)/4，是算术平均；换个口径就变成按记录加权，两个数会不一样。必须二选一并写死。

## 7. 页面结构

### 7.1 租户端（4 个主菜单）

**① 工作台**
- 顶部 3 个数字：本月应归档 / 已归档 / 逾期（不要 6 个）
- **第一屏主体是"我的待办"**：逾期（红）→ 临期（黄）→ 本周（灰），每条可一键上传
- 右侧：本集团归档率排名（前 5 + 后 3）
- 图表下沉到「统计」，首页不放环形图

**② 台账**（上传 + 档案合并，Tab 切换）
- Tab1「归档任务」：按公司/分类/期次列出待归档、待审核、已归档，支持从任务直接上传
- Tab2「全部档案」：**搜索框**（标题/备注/文件名）+ 公司/分类/年度/期次筛选 + 排序 + 分页 + 批量导出/打包下载
- 行操作：预览 / 下载 / 版本历史 / 关联任务 / 作废（**不做物理删除**；删除仅管理员 + 软删 + 留日志）

**③ 进度与统计**
- 公司 × 分类 横向对比矩阵（单元格可点进明细）
- 归档率趋势（近 12 月）
- 逾期清单（可导出为"催办单"）
- 导出 Excel/PDF

**④ 配置**
- 组织管理（树形，增/改/停用/排序）
- 分类与规则（含频次、截止日、模板、保留年限、适用公司）
- 成员与角色（邀请、停用、重置密码、批量导入、自定义角色 + 数据范围）
- 通知设置
- 操作日志（按人/按对象/按时间查）

### 7.2 平台超管后台（B 端）
- 租户列表（用量、状态、到期、开关）
- 行业模板包（发布/版本/下线）
- 全局字典与公告
- 跨租户操作审计

### 7.3 开通向导（SaaS 生死线，5 步）
```
1 填企业信息 → 2 选行业模板包 → 3 建组织树（可批量导入）
→ 4 邀请管理员 → 5 自动生成当年任务并预览
```
> 这一步做不顺，销售每签一单都要实施三天，规模化就死了。

## 8. 站内通知（v1 只做红点）

- 触发：任务临期/逾期、审核通过/驳回、账号开通、任务被指派
- 顶部铃铛显示未读数，点开列表页，点击即已读并跳转
- **补偿设计**：因为不推送，工作台必须把"未读待办"顶到第一屏；登录时弹一次"你有 N 项逾期"
- 预留 `notification.channel` 字段，v1.5 接企微/邮件不用改表

## 9. 行业模板包（SaaS 的核心资产）

一个模板包 = 一批 `category` 定义 + 默认规则 + 模板文件：
```
template_pack(id, industry, version, name, status, published_at)
template_item(pack_id, code, name, parent_code, frequency, due_offset, remind_days, required, retention_years, template_file)
```
首个包建议就叫 `环保台账-2026版`，包含你现在这 8 类。后续可扩：安全生产、消防、职业健康、危废专项。
**租户可继承模板后二次修改**（`source=template` 的可改不可删，`source=custom` 的随便改）。

## 11. 技术选型建议

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Java 17 + Spring Boot 3 | 政企私有化项目招人/交付最稳，信创适配成熟 |
| DB | PostgreSQL 14+ | 免费、可换人大金仓/达梦；`pg_trgm` 做模糊搜索 |
| 对象存储 | MinIO（私有化）/ 阿里云 OSS（SaaS） | 同一套 SDK，切环境只改配置 |
| 缓存 | Redis | 会话、未读数、统计缓存 |
| 前端 | Vue 3 + TS + Element Plus | 政务/国企风格匹配，组件全 |
| 部署 | Docker Compose 单机可跑 | **私有化单机部署能力是中标硬指标** |

**私有化双模式**：同一镜像，`DEPLOY_MODE=saas|standalone`，standalone 时关闭租户隔离逻辑、内置 License 校验。

## 12. 上线前检查清单

- [ ] 任意两个租户互相看不到数据（越权测试）
- [ ] 同一公司同一分类同期次不会重复生成任务（幂等）
- [ ] 免交的分类不计入分母
- [ ] 未来期次不计入逾期
- [ ] 归档率各页面数字一致（首页 / 统计 / 导出三处对齐）
- [ ] 删除只有超级管理员能操作，且是软删除 + 有日志
- [ ] 密码 argon2、登录失败 5 次锁定、首次登录强制改密
- [ ] 所有下载走签名 URL，URL 有有效期
- [ ] 换设备/换浏览器数据一致（当前版本不满足）
- [ ] 打包下载 500 个文件不超时
