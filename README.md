# 环智存 · 环保台账归档与合规管理平台

> 网盘管"存"，我们管"交没交"。

面向**集团总部 + 下属多家公司**的环保台账合规归档系统。把"每家公司每年必须交哪些环保资料"变成可配置规则，系统自动生成应归档清单、自动计算归档率、自动标注逾期与临期——**督察、审计、上级检查之前，不用再打电话催资料**。

---

## 它解决什么问题

一家环保集团，旗下 4 家子公司，每年要准备 8 类台账：环保制度、环保检查、环保培训、应急演练、月度/季度/年度总结、年度工作计划。行业惯例是：

- 资料散落在各公司电脑、微信、邮箱里
- 总部不知道谁交了、谁没交、交的是不是最新版
- 检查前一天还在微信群里挨个催
- 交上来的东西格式不统一，还得手工汇总成一张总表

**环智存的做法**：把"该交什么、什么时候交"写成规则，系统按规则自动生成任务（4 家公司 × 8 类 × 12 个月 ≈ 118 条），每家公司登录就看到自己欠了哪几期，总部一屏看全集团。

| | 网盘 / 知识库 | 环智存 |
|---|---|---|
| 谁定要交什么 | 人 | 规则自动生成 |
| 怎么知道漏交 | 靠催 | 应归档 − 已归档，实时可见 |
| 逾期多久了 | 不知道 | 逾期 23 天，红色标记 |
| 督察前准备 | 临时收资料 | 导出催办清单 |

## 功能

**核心**
- 组织树（集团 / 总部 / 子公司），支持停用，不物理删除
- 资料分类 + 归档规则：频次（月/季/半年/年/一次性）、截止日基准与偏移、提前提醒天数、适用公司
- **应归档任务由规则自动生成**，唯一索引保证不重复
- 期次显式化（`2026-10` / `2026-Q3` / `2026` / `ONCE`），不靠标题猜
- 不适用该分类的公司自动排除（不计入归档率分母）

**业务闭环**
- 上传 → 待审核 → 已归档 / 已驳回 → 可作废
- 文件版本管理，每版记录 SHA-256
- 已归档期次重复提交需显式选择「新版本」
- 审核、驳回、作废、删除全部写操作日志

**统计**
```
应归档 = 期间内已到期 且 未免交 的任务数
已归档 = 其中状态为「已归档」的任务数
归档率 = 已归档 ÷ 应归档        ※ 按任务计数，不做公司间算术平均
逾期   = 截止日 < 今天 且 未归档
临期   = 今天 ≤ 截止日 ≤ 今天 + 提醒天数
未来期间不计入任何分母
```

**权限**
- 4 个角色：系统总负责人 / 公司负责人 / 资料员 / 只读督察
- 数据范围：全集团 / 本公司子树
- 服务端逐接口校验，越权返回 403；密码 scrypt 加盐，5 次失败锁定

**多租户**
- 企业自助注册，自动建租户 + 组织 + 分类模板 + 当年任务
- 数据按 `tenant_id` 隔离，跨租户互不可见

## 快速开始（本地）

需要 **Node.js 22.5+**（使用了内置 `node:sqlite`）。**零第三方依赖，不需要 npm install。**

```bash
npm start
# 或
node --experimental-sqlite server/index.js
```

打开 <http://127.0.0.1:3000>。首次启动自动建库并生成演示数据（1 个集团、4 家公司、8 类资料、118 条任务）。

## 部署到 Render（公网访问）

### 1. 推到 GitHub

把本目录内容作为一个仓库推送上去（`.gitignore` 已排除 `data/`，不要提交本地数据库）。

### 2. 在 Render 建服务

1. 注册 <https://render.com>（可用 GitHub 账号登录）
2. 点 **New +** → **Blueprint**
3. 选择你的仓库 → Render 会读取 `render.yaml` 自动创建服务
4. 等待 2～3 分钟，得到 `https://xxx.onrender.com`

如果没有自动识别 Blueprint，手动创建 **Web Service** 也可以，填：

| 配置项 | 值 |
|---|---|
| Runtime | Node |
| Build Command | `npm install --omit=dev` |
| Start Command | `node --experimental-sqlite server/index.js` |
| Health Check Path | `/api/health` |
| 环境变量 `NODE_VERSION` | `24` |
| 环境变量 `HOST` | `0.0.0.0` |

### 3. ⚠️ 免费版的数据是临时的

Render 免费实例**没有持久磁盘**，重新部署或休眠重启后 `data/` 会重置，数据库和上传文件都会回到初始演示状态。

- 用于**演示和比赛**没问题（每次打开都是干净的演示数据）
- 要保留数据，需要：挂持久磁盘（付费）／换 Railway、Fly.io ／自建服务器

### 4. 另一种部署方式：Docker

```bash
docker build -t huanzhicun .
docker run -d -p 3000:3000 -v $(pwd)/data:/app/data --name hzc huanzhicun
```
`-v` 把数据挂到宿主机，重启不丢。**私有化交付给企业客户时用这个方式。**

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 运行时 | Node.js 22.5+ | 使用内置 `node:sqlite`、`node:http` |
| 数据库 | SQLite | 单文件，零运维；可平滑迁移 PostgreSQL |
| 存储 | 本地磁盘 | 生产环境建议换对象存储（OSS / MinIO） |
| 前端 | 原生 JS + CSS | 无构建步骤、无框架、无 CDN 依赖，可离线运行 |
| 依赖 | **0 个** | 不需要 `npm install`，没有供应链风险 |

## 已知边界

- AI 能力（扫描统计、制度比对、报告生成）尚未接入
- 通知仅站内红点，未接企微 / 钉钉 / 邮件
- 无全文检索与 OCR（当前检索标题、备注、文件名）
- 无打包下载（仅单文件下载 + CSV 导出）
- 单机 SQLite，适合 50 人以内；更大规模建议迁移 PostgreSQL
